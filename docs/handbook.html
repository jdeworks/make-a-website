1. Prerequisites

Before you start, make sure you have these tools installed on your computer:

  • Node.js (version 18 or newer) — the runtime that powers your project. Download it from nodejs.org.
  • Git — version control for your code. It often comes pre-installed on Mac and Linux. Windows users can get it from git-scm.com.
  • A code editor — VS Code is recommended. It is free, works on all platforms, and has great extensions for web development.

To check if Node.js and Git are installed, open a terminal and run:

node --version
git --version

You should see version numbers printed. If you get "command not found," install the missing tool first.

2. Getting Started

The WebStarter Kit works by asking you a few questions about what you want to build, then scaffolding a project for you.

Here is the general flow:

  1. Describe your idea. What kind of website? Who is it for? A portfolio, a blog, a small business page, a web app?
  2. Pick a framework. Start with plain HTML/CSS/JS (vanilla) if you are new. You can upgrade to React or Vue later.
  3. Build it. The template gives you a starting point. Customize the design, add your content, build your features.
  4. Test it. Write tests to make sure things work. Run them before every big change.
  5. Deploy it. Put it on the internet. Static sites go to GitHub Pages. Server apps go to Railway.

If you are using an AI agent, it will walk you through each step interactively.

3. Choosing a Framework

You have several options. Here is a quick comparison:

Option Best For Complexity
Vanilla (HTML/CSS/JS) Simple sites, learning the basics Low
React Interactive apps, component-heavy UIs Medium
Vue Similar to React, gentler learning curve Medium
Astro Content-heavy sites, blogs, docs Medium

Recommendation: if you are unsure, start vanilla. You can always upgrade to React later using the upgrade guide.

4. Project Structure

A well-organized project is easier to work on. Here is a typical layout:

my-website/
  public/           # Static files (images, favicon)
  src/              # Your source code
    components/     # Reusable UI pieces
    pages/          # Page files
    styles/         # CSS files
    utils/          # Helper functions
  tests/            # Test files
  package.json      # Dependencies and scripts
  README.md         # Project documentation

Keep related files together. Name files clearly. Do not overthink it at the start — you can reorganize later.

5. Testing

Tests catch bugs before your users do. The WebStarter Kit uses Vitest, a fast and modern test runner.

To run your tests:

npm test

A simple test looks like this:

import { describe, it, expect } from 'vitest';
import { add } from '../src/utils/math.js';

describe('add', () => {
  it('adds two numbers', () => {
    expect(add(2, 3)).toBe(5);
  });
});

Rule of thumb: write a test for every function that takes input and returns output. Run tests after every significant change.

6. Security

Even simple websites need basic security. Follow these essentials:

  • Never put secrets in your code. API keys, passwords, and tokens go in environment variables (a .env file), not in your source code.
  • Add .env to .gitignore. This prevents accidentally uploading secrets to GitHub.
  • Validate user input. If your site has forms, check that the data looks right before using it.
  • Keep dependencies updated. Run npm audit regularly to check for known vulnerabilities.
  • Use HTTPS. GitHub Pages and Railway both provide this automatically.

7. Design

The WebStarter Kit uses Tailwind CSS for styling. Tailwind gives you utility classes that you apply directly in your HTML.

For example:

<h1 class="text-3xl font-bold text-gray-900">Hello</h1>
<p class="mt-2 text-gray-600 leading-relaxed">Welcome to my site.</p>

Key design principles:

  • Whitespace is your friend. Give elements room to breathe. Cramped layouts feel amateur.
  • Limit your color palette. Pick one primary color and use gray for everything else.
  • Use good typography. Inter or system fonts work great. Set comfortable line heights.
  • Be consistent. Use the same spacing, colors, and font sizes throughout.
  • Mobile first. Design for small screens first, then add styles for larger ones.

For more detailed design guidance, reference the make-it-look-good style guide.

8. Hosting a Static Site

If your site is just HTML, CSS, and JavaScript (no server), GitHub Pages is the easiest way to put it online. It is free.

  1. Push your code to a GitHub repository.
  2. Go to Settings > Pages in your repo.
  3. Set the source to your main branch (and the /docs folder or root, depending on your setup).
  4. Your site will be live at https://yourusername.github.io/your-repo.

Every time you push changes, the site updates automatically.

9. Hosting a Server App

If your project has a backend (Express, API routes, a database), you need a server host. Railway is a good choice for small projects.

  1. Sign up at railway.app using your GitHub account.
  2. Create a new project and connect your GitHub repo.
  3. Railway detects Node.js automatically and deploys your app.
  4. Add environment variables in the Railway dashboard (never in code).

For databases, SQLite works well for small apps. Railway also supports PostgreSQL if you need something larger.

10. Upgrading to React

Started with vanilla HTML/JS and want more power? You can migrate to React without starting over.

The general approach:

  1. Install React and a build tool (Vite is recommended).
  2. Convert your HTML pages into React components.
  3. Move your logic into React hooks and state.
  4. Update your tests to use React Testing Library.

The AI agent can handle this migration for you — just ask it to upgrade your project to React.

11. CI/CD with GitHub Actions

CI/CD means your tests run automatically every time you push code. If tests fail, you know before anything breaks in production.

GitHub Actions handles this for free. The WebStarter Kit includes a workflow that:

  • Runs npm test on every push and pull request.
  • Checks your code with a linter.
  • Deploys automatically when tests pass on the main branch.

You do not need to set this up manually — the AI agent configures it for you as part of the project setup.
